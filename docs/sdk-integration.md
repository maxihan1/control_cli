# QA Hub SDK 연동 가이드

Unity 게임의 QA 빌드에 QA Hub SDK를 넣는 방법입니다. Android 게임과 Windows 게임 모두 같은 방법으로 넣습니다. 명령 한 줄을 실행하고 평소처럼 빌드해서 보내 주시면 됩니다.

## 준비물

- Unity 2021.3 LTS 이상으로 만든 Android 또는 Windows 게임 프로젝트
- Node.js 22 이상
- QAhub-0.13.0.zip (이 가이드와 함께 받은 파일)

## 1. SDK 넣기

1. QAhub-0.13.0.zip의 압축을 풉니다. QAhub 폴더가 생깁니다.
2. Unity 에디터를 닫습니다.
3. 터미널에서 QAhub 폴더가 있는 위치로 이동해 아래 명령을 실행합니다.

```
node QAhub/dist/main.js instrument <Unity 프로젝트 폴더>
```

`<Unity 프로젝트 폴더>` 자리에는 프로젝트 폴더의 경로를 씁니다. Assets 폴더와 Packages 폴더가 들어 있는 폴더입니다.

Windows의 명령 프롬프트나 PowerShell에서는 아래처럼 씁니다.

```
node QAhub\dist\main.js instrument C:\Projects\MyGame
```

아래처럼 나오면 끝난 것입니다.

```
QA Hub SDK(0.13.0)를 Packages/QAHubSDK에 추가했습니다
asmdef 참조 추가: Assets/…/Game.asmdef
QA 빌드 설정을 ProjectSettings/ProjectSettings.asset에 추가했습니다. 이대로 빌드하면 SDK가 들어갑니다. 바뀐 파일은 커밋하지 마세요.
```

이 명령은 프로젝트에서 세 군데를 바꿉니다.

| 바뀌는 곳 | 내용 |
|---|---|
| `Packages/QAHubSDK` 폴더 | SDK가 들어 있는 폴더가 새로 생깁니다. |
| 게임의 asmdef 파일 | SDK를 참조하는 줄이 하나 늘어납니다. |
| `ProjectSettings/ProjectSettings.asset` | QA 빌드에만 SDK를 넣는 설정이 들어갑니다. |

**주의**

- 바뀐 내용은 게임 저장소에 커밋하지 마세요. 커밋하면 출시 빌드에도 SDK가 들어갑니다.
- 빌드 서버를 쓴다면 QA 빌드를 만들 때만 이 명령을 실행합니다.
- 직접 빌드한다면 빌드가 끝난 뒤 바뀐 내용을 되돌립니다. 새로 생긴 `Packages/QAHubSDK` 폴더도 지웁니다.

출력에 `경고:`로 시작하는 줄이 있으면 그 파일에서는 터치 입력이 들어가지 않습니다. 그 줄에 적힌 대로 고쳐 주세요.

## 2. 빌드와 자료 보내기

아래 여덟 가지를 보내 주세요.

- **QA 빌드**: SDK를 넣은 뒤 평소대로 만든 빌드. 운영 서버가 아니라 QA 서버에 접속하도록 만들어 주세요. Android 빌드와 Windows 빌드에는 같은 버전의 SDK를 넣어 주세요.
  - Android: APK
  - Windows: 빌드 폴더 전체를 묶은 zip. 실행 파일(.exe)은 zip 맨 위나 폴더 하나 아래에 하나만 둡니다.
- **1번 명령의 출력**: 화면에 나온 내용 전부
- **QA 서버 주소**: QA 빌드가 접속하는 서버의 주소
- **테스트 계정**: 아이디와 비밀번호 여러 개. 테스트 작성, 테스트 실행, 테스트 기기마다 따로 쓰고 동시에 접속합니다. 같은 계정으로 두 곳에서 접속할 수 있는지도 알려 주세요. 소셜 로그인만 있는 게임이면 게스트 로그인이나 개발용 로그인을 열어 주세요.
- **기획서**: 게임 규칙, 수치표, 확률표. 수치가 실제 게임 데이터와 같은지 확인한 뒤 보내 주세요.
- **테스트용 명령**: GM 명령이나 어드민 API의 목록과 사용법. 아래 일을 할 수 있어야 합니다. 켜고 끄는 방식의 명령은 따로 표시해 주세요.
  - 캐릭터와 계정 상태 바꾸기: 체력, 재화, 아이템, 레벨, 위치 이동, 몬스터 생성 등
  - 계정을 기준 상태로 되돌리기: 재화, 가방, 레벨, 길드, 우편 등
  - 화면에 보이지 않는 서버 값 조회: 체력, 능력치 등
  - 멀티플레이 게임은 다른 플레이어(봇) 켜기와 끄기
- **서버 로그**: 게임 서버 로그나 이벤트 기록을 볼 수 있는 방법
- **게임 정보**: Unity 버전, 입력 방식(Input Manager, Input System, 둘 다), 사용하는 UI(uGUI, TextMesh Pro, UI Toolkit), 화면 방향, 서버 통신 방식(REST, 소켓), 첫 실행 때 뜨는 화면(약관, 권한, 추가 다운로드, 튜토리얼). Windows 게임은 패드 지원 범위(패드로 조작하는지, 패드를 연결하면 버튼 그림만 바뀌는지)와 패드를 읽는 방식(Input System, Rewired, Steam Input)도 알려 주세요.

아래 자료가 있으면 함께 보내 주세요.

- 버튼을 눌러야 열리는 화면까지 담은 화면 흐름도
- 실행할 때마다 이름이 바뀌는 오브젝트, 장면이 바뀌어도 계속 떠 있는 UI
- 저절로 다음 화면으로 넘어가는 화면과 넘어가기까지의 시간
- 목록 UI에서 새 항목이 붙는 위치(맨 앞, 맨 뒤)
- 확률표가 있는 게임은 실제 뽑기 결과 기록

Android 게임은 빌드할 때마다 versionCode를 올려 주세요. 버전이 같으면 테스트 환경에 새 빌드가 설치되지 않습니다.

## 지원하는 Unity 버전

| Unity 버전 | 지원 여부 |
|---|---|
| 2021.3 LTS, 2022.3 LTS, 6000.0, 6000.3 | 지원합니다. |
| 2023.1, 2023.2, 6000.1, 6000.2 | 테스트되지 않았으나 지원될 것으로 예상됩니다. 이 버전을 사용한다면 미리 알려 주세요. |
| 2020.3 이하 | 지원하지 않습니다. |

Windows 게임의 IL2CPP 빌드는 테스트되지 않았으나 지원될 것으로 예상됩니다. Mono 빌드는 지원합니다.
